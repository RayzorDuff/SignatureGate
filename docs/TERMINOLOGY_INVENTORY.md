# Terminology inventory and release checklist

Display terminology describes a deployment's presentation. It does not rename identity, capacity or permission contracts, grant access, merge parties or rewrite executed documents.

## Current concepts

- Individual and Company identify party kinds.
- Participant and Contributor identify independent capacities.
- Facilitator/Spiritual Practitioner and review/administration appointments characterize access.
- The general practitioner label defaults to Spiritual Practitioner.
- A separately reserved regulated appointment remains distinct and inactive until designed and accepted.

Different deployments may choose different display labels without conflating appointments or permissions. Keep the detailed source-to-label inventory and actual document/configuration mappings private.

## Initialization and existing overrides

The explicit repeatable initializer creates missing registered concepts and defaults. Reapplication preserves installed labels, activation choices and attribution; it does not grant roles. Existing accepted label changes require the audited terminology API, not a forced initializer overwrite.

The initializer currently retains the legacy Participant-capacity display label. Phase 3 must revise that default to Participant together with the accepted interface changes and behavioral expectations. Do not claim the interface rename is complete just because documentation uses the intended term.

## Phase 3 acceptance

1. Review every active page, navigation group, dialog, notification, report and generated document label.
2. Keep literal compatibility identifiers stable; change their presentation through the intended configuration boundary.
3. Update Participant/practitioner labels, initializer defaults and behavioral checks together.
4. Verify the general practitioner and reserved regulated appointments remain distinct; label activation grants no access.
5. Verify an alternate deployment's labels without source edits or changes to signed-document history.
6. Review actual document templates privately with the intended authority; preserve executed documents.
7. Update the final screen inventory after navigation acceptance and before release packaging.

Public acceptance records contain only sanitized pass/fail, source/software provenance and remaining gaps. Actual organization names, contacts, account mappings, document recipients and operational examples remain private.
